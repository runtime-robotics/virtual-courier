# Решение «Виртуального курьера»

Робот строит карту по лидару и исследует граф ячеек. Одометрия даёт перемещение, IMU корректирует направление. A* прокладывает путь с учётом габаритов робота и паллет. Станции определяются по ArUco и цвету пола. После остановки на станции робот ждёт загрузку, затем продолжает поиск. Перед истечением времени или после обхода станций возвращается к старту и выгружает грузы.

Карта и маршрут публикуются в `/map` и `/plan` для RViz. Алгоритм не читает сценарии, служебные топики судьи или истинную позу робота. Окно камеры OpenCV не открывается.

## Запуск

В уже работающем контейнере, после сброса сцены к началу попытки:

```bash
docker exec -it vc_solution bash
source /opt/ros/humble/setup.bash
python3 /ros_ws/src/solution/scripts/courier_node.py
```

Запускайте только один экземпляр управления. Повторный запуск ноды посреди заезда не восстанавливает её карту и начальную систему координат. Для новой попытки остановите ноду и сбросьте сцену.

Обычный запуск Compose с `gui:=true` оставляет ручной запуск миссии. Для автоматического старта вместе с GUI передайте `run:=true`. Официальная команда `ros2 launch solution start.launch.py gui:=false` запускает миссию автоматически. SLAM и Nav2 одновременно с этой нодой включать не нужно: она сама строит карту, планирует путь и публикует команды движения.

## Проверки

```bash
docker exec vc_solution bash -lc 'source /opt/ros/humble/setup.bash; python3 /ros_ws/src/solution/tests/test_navigation.py'
docker exec vc_solution bash -lc 'source /opt/ros/humble/setup.bash; colcon build --symlink-install --packages-select solution'
```

Оценивайте заезд по протоколу `results/*.json`: доставленные грузы, время, касания и потери. Датчик `cargo_count=0` после выгрузки сам по себе не подтверждает доставку. Баллы защиты и инженерной книги не входят в результат симулятора.
